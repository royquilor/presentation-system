# Executive Pitch System (Markdown-First)

## Context

I needed to communicate a structural workflow issue to a VP of Product.

This wasn’t a design critique.  
It wasn’t a feature proposal.  
It was a systems-level observation that required clarity, neutrality, and control.

The presentation had to:

- Work async or live  
- Be structured, not decorative  
- Allow rapid iteration with AI  
- Reflect my taste  
- Feel calm and intentional  

I initially tried using Gamma.

It worked.  
But it didn’t feel like mine.

---

## Problem

Most presentation tools optimise for speed and visual polish.

But high-stakes conversations require something different:

- Control over structure  
- Control over tone  
- Control over hierarchy  
- Control over pacing  
- Control over iteration  

Templates introduce bias.  
Slides introduce noise.  
Design layers distract from thinking.

The friction wasn’t technical.  
It was philosophical.

I wanted full ownership of the structure.

---

## Observations

### 1. Markdown forces clarity
When formatting disappears, only logic remains.

### 2. AI works better with structured text
Claude can reason, restructure, and refine markdown far more effectively than slide layouts.

### 3. Version control reduces anxiety
GitHub history makes iteration safe.

### 4. Deployment creates confidence
Vercel allows instant publishing without design compromises.

### 5. Keyboard navigation improves flow
It feels intentional and controlled during live walkthroughs.

### 6. Templates subtly shape thinking
Tools like Gamma are powerful, but their structure influences the narrative.

This was not a design problem.  
It was a thinking problem.

---

## Proposal

Instead of forcing slides to behave like documents, I built a markdown-first presentation system.

### Stack

- Markdown → foundation  
- Claude → structural refinement  
- Cursor AI → site generation  
- GitHub → version control  
- Vercel → deployment  
- Keyboard navigation → live control  

### Result

- Fully custom  
- Fast to iterate  
- Structured  
- Reusable  
- Taste-aligned  

Not a slide deck.

A presentation system.

---

## Risks

- Overbuilding when a simple deck would suffice  
- Optimising for control over speed  
- Investing time in infrastructure instead of message  
- Mistaking craftsmanship for necessity  

This approach is not always required.

It makes sense when:

- The conversation is high-stakes  
- Structure matters more than decoration  
- Control influences confidence  

---

## Next Steps

For now, this remains a proof-of-thinking artifact.

Possible future directions:

- Turn into a reusable template  
- Extract into a lightweight framework  
- Offer as a tool for designers pitching founders  
- Keep as an internal system for high-leverage conversations  

The real outcome was not the website.

It was clarity.
