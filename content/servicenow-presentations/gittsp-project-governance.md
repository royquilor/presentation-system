# Project Governance
> Governance structure, communication, RACI, and processes for Group IT Transition to ServiceNow

**Author:** Jessie Gisler
**Date:** 20 November 2025
**Source:** https://datacomgroup.atlassian.net/wiki/spaces/GITTSP/pages/40269873344

---

## 🎯 Context

Project Governance defines the structure, responsibilities, communication cadence, and processes for the Group IT Transition to ServiceNow project. It ensures strategic oversight, clear decision-making authority, and consistent risk and issue management throughout the project lifecycle.

---

## 🔍 Problem

Without defined governance, project direction, prioritisation, scope changes, and escalations lack clarity. The project requires clear accountability for phase gates, FSD alignment, budget, resourcing, and RAID management to deliver successfully.

---

## 📋 Observations

**1. Executive Sponsor layer**
GLT Mark Hile and Director Exec Sponsor Shawn Sutton provide strategic oversight, funding approval, and escalation resolution; approve project, funding, and major changes; resolve escalations outside Steering scope; monthly updates to Sponsor and Executive Sponsor.

**2. Steering Committee**
Project Sponsor Shawn Sutton, PM Jessie Gisler, Members Julian Buckley, Sumindre Gunawardane, Clinton Cooper, Joe Thornley; Attendees Josh Jacobs, Jason Chau, Jonathan Lim; fortnightly cadence for Project Status Review, Escalations, Decisions; responsibilities include approving phase gates (Discovery complete → Build → Deployment), prioritising scope, managing FSD dependencies, reviewing risks and issues monthly, monitoring budget and resourcing.

**3. Project Delivery Team**
PM Jessie Gisler, Discovery Lead Jonathan Lim; twice weekly Project Team Meetings; daily PM Team Check-ins when in Delivery; delivers agreed phase outputs, manages RAID log, reports progress to Steering Committee.

**4. Communication and reporting**
Project Status Report available in Jira each fortnight to Project Sponsor, Steering Committee, FSD Programme; Steering Committee Meeting fortnightly/monthly; Informal Project Status Meeting TBC as required.

**5. RACI matrix**
Exec Sponsors accountable for Project Scope Approval and Governance Structure; Steering Committee accountable for Phase Decisions; Project Team accountable for Discovery Planning & Execution, Migration Schedule, Change Management, BAU Handover; FSD Programme consulted on Migration Schedule and Change Management.

**6. Project processes**
Project Change Management via Project Variation Request for scope, deliverables, plan or budget changes; Risk Management using Risk Register, revisited at every status meeting; Issue Management via Issue Register with PM allocation and resolution tracking; Issue Escalation path from team member → PM → Project Variation Request → Management/Governance Board.

**7. Governance cadence**
Executive Sponsor: Monthly; Steering Committee: Fortnightly; Project Delivery Team: Twice weekly (plus daily check-ins in Delivery).

**8. Risk and issue tracking**
RAID managed via Power BI; all risks and issues recorded, monitored, and closed at project end.

---

## 💡 Proposal

Operate the project under the defined governance structure with clear accountability at each level.

- Execute fortnightly Steering Committee meetings for status, decisions, and RAID review
- Maintain Project Status Report in Jira for transparency
- Document all scope, plan, or budget changes via Project Variation Request
- Escalate unresolved issues through PM to Management or Governance Board
- Revisit risk register at every status meeting

*Governance ensures the project remains on track, aligned with FSD, and responsive to risks and issues.*

---

## ⚠️ Risks

- **Escalation delays:** Unresolved issues may delay delivery if escalation path is not followed promptly.
- **FSD alignment:** Steering Committee must actively manage FSD dependencies; misalignment could impact milestones.

---

## ✅ Next Steps

1. **Confirm Steering Committee cadence** — Establish fortnightly vs monthly for Steering Committee meetings.
2. **Distribute RAID access** — Ensure Power BI RAID register is accessible to all governance members.
3. **Document variation process** — Finalise Project Variation Request template and approval workflow.
